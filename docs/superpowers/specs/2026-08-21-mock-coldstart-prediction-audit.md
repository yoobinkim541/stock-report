### 국내 정체의 구조적 원인 (실측 확인)
- `KR_MOCK_MIN_HOLD_DAYS=60` (기본값·**캘린더 일**, `crons/kiwoom_mock_track.py:98`)
- 현 보유 3종목 편입일: 068270/009540/207940 = 2026-07-29, 035720 = 2026-07-30
- → **2026-09-27까지 청산 불가** (37일 더). `KR_MOCK_MAX_POS=3`, 현금 ₩1,002(≈0)
- → 팔 수 없고 살 돈도 없음 = 새 결정 생성 자체가 불가능

크론은 정상 작동 중(12일 연속 "리밸런스 계획 0건") — 인프라 장애가 아니라 **설계된 회전율
억제(무거래 밴드 25% + 히스테리시스 + 최소보유 60일)의 부작용**.

이론상 최대치로도 25건(현재 기록된 유효 매수 결정 총수)이라 40건 문턱은 **영원히 도달 불가**.

## 2. 편입/편출 예측력 — 측정 불능 상태였음 (핵심 발견)

### 모델 구조
순수 ML 분류기가 아니라 **선형 가중합**(`ml/kr_policy.py:27-37`, `ml/us_policy.py:21-32`):

```
KR: ranker .30 + fund .15 + signal .15 + hi52 .15 + lowvol .10 + conf .05 + mom .05 + mom12 .05
US: ranker .40 + value .20 + quality .20 + mom .10 + conf .10  (나머지 0 — 수집만)
```
`ranker`만 LightGBM(`ml/ranker.py` LGBMRanker·lambdarank), 나머지는 규칙 기반.
**주간 재학습은 7주간 단 한 번도 채택된 적 없음**(표본 미달로 게이트 미통과).

### 구간제한(range restriction) — 실측
2026-08-21 실제 국내 신호 20종목으로 측정:

| | 표준편차 | 범위 |
|---|---|---|
| 전 유니버스(20종목) | 0.1222 | 0.315 ~ 0.734 |
| **실제 원장에 남는 상위 3개** | **0.0136** | 0.701 ~ 0.734 |

→ 분산비 u = 0.111 (**9.0배 구간제한**)

Thorndike Case II 감쇠식 `r_obs = r_true·u / √(1 + r_true²(u²−1))` 적용:

| 참 IC | 관측될 IC |
|---|---|
| 0.10 | 0.011 |
| 0.20 | 0.023 |
| **0.30** | **0.035** |
| 0.50 | 0.064 |

**참 IC가 0.30(강한 엣지)이어도 관측치는 0.035로 엣지 문턱(0.05) 미달.**
즉 관측된 IC ≈ 0 은 "선택 스킬 없음"의 증거가 **아니라** 측정 장치가 엣지를 탐지할 수
없는 상태의 증거였다.

### 미검증 가중치
`backtest/{kr,us}_policy_backtest.py`(20~25년·DSR/PBO·무생존편향)는 **가격 축만** 검증:
- KR `OBSERVE` — 순초과 +4.29%/yr이나 DSR 0.080·PBO 18.6% (엣지 주장 불가)
- US `NO-GO` — 순초과 **-6.06%/yr**·DSR 0.003·MDD 위반 (QQQ 매수보유에 패배)

**ranker/fund/signal/conf (KR 가중치의 0.65)는 검증 대상에 아예 없었음.**

## 4. 의도적으로 하지 않은 것 (그리고 이유)

### 라이브 모의의 회전율 파라미터는 건드리지 않음
`MIN_HOLD_DAYS`/`REBAL_BAND`/`MAX_POS`를 콜드스타트용으로 완화하면 표본은 늘지만
**라이브 모의의 존재 이유(실운용 현실성 시뮬레이션)를 훼손**한다. 최소보유 60일은
비용 OOS 실증(과잉거래가 순수익 ~2.4%p 잠식)으로 채택된 값이다.
섀도 원장이 표본 문제를 완전히 해결하므로 라이브를 왜곡할 이유가 사라졌다.

### 25년 point-in-time 재구성(ranker/fund 축)은 만들지 않음
과거 시점 펀더멘털 + 각 리밸런스 시점 랭커 재학습을 25년치 복원하는 것은
룩어헤드 편향 위험이 매우 크고(잘못하면 결과가 무용지물보다 나쁨), 수 주 규모 작업이다.
섀도 축적으로 **전진 측정**하는 쪽이 통계적으로 더 방어 가능하다.

## 5. 미성숙 이상 추적 — 근본 원인 2건 확정 (2026-08-21 당일 해결)

"20거래일 지났는데 미성숙" 이상을 파고든 결과, **서로 독립적인 버그 2개**가 겹쳐 있었다.
둘 다 예외·로그 없이 조용히 실패해 발견이 늦었다.

### 원인 1 — tz-aware/naive 혼재로 교집합 0
`_default_price_fn`이 종목·벤치마크를 `index.intersection()`으로 정렬하는데, 캐시 시점에
따라 tz 유무가 갈렸다. 실측:

| 종목 | 벤치마크 | 교집합 |
|---|---|---|
| INTC `tz=None` | QQQ `tz=America/New_York` | **0건** |
| 종목 `tz=None` | ^KS11 `tz=Asia/Seoul` | **0건** |

→ `len(common) <= horizon` True → None → 영원히 미성숙.
캐시 재작성 타이밍에 따라 tz 유무가 갈려 **비결정적으로 일부만** 성숙 → 더 안 보였다.

**조치**: `ohlc_utils.align_common_index()` / `to_naive_days()` 신설.
⚠️ `tz_convert(None)`은 UTC로 옮겨 날짜가 하루 밀림(서울 06-01 00:00+09 → UTC 05-31) —
벽시계 보존하는 `tz_localize(None)` 사용.

### 원인 2 — 디스크 캐시 나이 검사 부재
`load_cached_ohlc`는 staleness 검사가 **전혀 없어** 7/31에 쓰인 parquet를 무기한 서빙.
US 종목이 7/31에서 멈춘 채(벤치 QQQ는 8/14) 7/8 이후 결정이 공통 거래일 18개(<20)로 갇힘.
**tz 수정만으로는 안 풀렸다.**

**조치**: `market_data.load_close_series_upto(symbol, need_last)` — 목표 거래일에 못 미치면
라이브 재조회 후 캐시와 병합(충분하면 재조회 안 함). 병합 시에도 tz 정규화 필수 —
안 하면 concat 인덱스가 object로 섞여 groupby가 깨지고 **병합이 조용히 실패**해 낡은
캐시가 그대로 반환된다(실측 확인).

### 효과 (라이브 백필 실행)

| | 성숙 | 적중률 | 누적 순초과 |
|---|---|---|---|
| KR | 14 → **20** (+6) | 42.9% → 55.0% | +4.55% → +8.80% |
| US | 27 → **38** (+11) | 40.7% → 47.4% | -0.88% → -0.30% |

**갇혀 있던 27건 즉시 회수. US는 40건 문턱까지 2건 남음.**
IC는 -0.023→-0.057 / -0.031→-0.104로 내려갔으나 CI가 여전히 0을 포함 — 표본이 늘어
추정이 바뀐 것이지 결론(유의하지 않음)이 바뀐 게 아님.
