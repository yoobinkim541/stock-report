# 위키 원문 기반 지식 갱신

기존 source_digest는 최근 수집 내용의 색인이다. 지식 생성은
`reports/wiki_distillation.py`에서 수행한다.

## 동작

- 승인된 배포에서는 원문 기반 생성이 기본이다. 기존 예약 작업에서도 적용된다.
  `WIKI_FULLTEXT_SYNTHESIS_ENABLED=0` 또는 Python `run(fulltext=False)`로 끌 수 있다.
- 활성화하면 최근 72시간의 로컬 이벤트 파일을 한 번 스트리밍으로 읽고,
  후보의 evidence ID와 일치하는 전문을 선택한다. 오래된 출처도 보관된
  추출 본문과 manifest의 출처·완전성 정보를 통해 읽을 수 있다.
- 현재 입력 예산은 주제당 최대 8건, 본문당 20,000자, 합계 80,000자다.
  본문을 잘라 성공으로 처리하지 않는다. 예산 초과 또는 불완전한 본문은
  `chunk pipeline required` 실패로 남긴다. 긴 원문 분할 증류는 아직 미구현이다.
- Telegram/Arca 전문은 제공자·HTTPS 출처·추출 범위·완전성이 맞아야 사용한다.
  커뮤니티 주장에는 미검증 표시를 유지하고 생성 초안의 신뢰도는 0.5 이하로 둔다.
  FRED 시리즈 설명은 정의 자료로 사용할 수 있지만 수치 스냅샷은 기사로 보지 않는다.
  모든 첨부 기사에 개별 출처 검증을 적용하며 정상 기사 하나로 잘못된 출처를
  통과시키지 않는다. 제공자별 URL 검증은 일반 뉴스 분류로 우회할 수 없다.
  FRED 전문 설명은 `series_notes`로 분류한다. 숫자 스냅샷은 원문 수집 기록을
  유지하되 기사 증류 입력에서는 제외하며, 혼합 주제의 정상 본문을 막지 않는다.
- 기존 생성 문서의 본문과 출처도 함께 제공한다. 새 문서는 draft로 저장한다.
- 기사 근거의 S번호 인용을 검사하고 실제 수집 URL로 연결한다.
  URL만 있고 내부 evidence ID가 없는 자료도 URL 인용으로 처리한다.
  원문이 없는 source 페이지는 생성하지 않고 재시도 가능한 실패로 기록한다.
- evidence_fingerprint가 달라지면 created/skipped 주제도 재검토한다.
  동일 근거에서는 완료/건너뜀을 유지하고 실패 재시도는 기존 상한을 따른다.
- 오래 검토하지 않은 주제를 우선 처리해 근거가 많은 일부 주제가 처리량을 독점하지 않게 한다.
- 실패해도 기존 문서 ID를 유지하며 최대 3회 재시도한다. 보관된 문서는 되살리지 않는다.
- 어휘 유사도만으로 발견한 다른 문서는 본문을 덮어쓰지 않고 연결한다.
- 자동 만료 정리는 지식 문서, 출처·근거가 있는 문서, 부모·자식 및 참조 관계를
  보존한다. 오래된 지식은 검토 대상으로 남기며 날짜만으로 숨기거나 삭제하지 않는다.
- Markdown 내보내기에도 전문과 ID 기반 연결, 제목 별칭을 남긴다.
- 출처 URL과 원본·추출 본문 경로는 4,096자 이내에서 식별자를 그대로
  유지한다. 긴 참조를 잘라 다른 주소로 만들지 않고 상한 초과는 제외한다.
  보관 경로 보존은 reports의 raw/text 하위로 제한하며 민감값과 다른 개인
  경로의 마스킹은 유지한다. 과거에 이미 잘리거나 마스킹된 참조는 이 수정으로
  복원되지 않으며, 원본 manifest와 일치 여부를 별도 검토해야 한다.
- 숫자 스냅샷으로 제외한 이벤트는 연결된 보관 본문 경로에서도 기사 입력으로
  다시 들어오지 않는다. 출처 중복·위키 연결 검사도 잘린 URL 접두사가 아닌
  전체 식별자로 비교한다.
- 공개 Telegram 메시지의 전체 추출 본문은 `body_raw`와 보관 텍스트에
  저장한다. 기존 3,000자 제한은 표시·분류용 텍스트에만 적용한다. 같은 채널의
  정확한 메시지 URL과 공개 메시지 카드가 확인된 경우에만 `public_message`
  완전성을 남긴다. 제목 대체 경로는 미리보기로 표시하고 전문 증류에 쓰지 않는다.
  이 완전성은 메시지의 텍스트 범위이며, 첨부 이미지·연결된 외부 기사까지
  읽었다는 뜻은 아니다. 원본 HTML은 직렬화된 메시지 DOM 조각이다.
  기존 미리보기는 이력에 남기고 새 전문을 추가하며 같은 전문 재수집은 중복 제거한다.

## 활성화 전 확인

모델 호출은 기존 `_try_llm_prompt` 경로를 사용한다. 해당 환경의 Codex/Hermes
및 Gemini 대체 경로로 기사 본문과 기존 위키 내용이 전달될 수 있다.
이 데이터와 처리 경로에 대한 승인을 받은 뒤 활성화한다.
`run(dry_run=True, fulltext=True, limit=1)`은 저장하지 않지만 모델 호출은 한다.

## 검증과 한계

`uv run pytest -q tests/test_wiki_distillation.py tests/test_wiki_knowledge_refresh.py tests/test_wiki_evidence_fingerprint.py tests/test_wiki_merge_overflow.py tests/test_wiki_refresh_retry.py`

기존 위키 전체를 일괄 재작성하지 않는다. 기존 배치 제한 내에서 갱신하며,
원문 확보 여부·모델 품질·처리량은 운영 결과로 추가 확인해야 한다.
원문을 실제로 읽은 출처와 과거 지식의 문맥으로만 보존한 출처를 구분한다.
보관된 본문도 없는 링크 목록만으로 추론을 채워 넣지 않는다. 정상 JSON 객체·배열은
모델 전달 단계에서 6,000자로 잘리지 않으며, 100,000자를 넘는 응답은 실패로 처리한다.
